## 1. 这条路线最有效：读 uiautomator 文本，而不是逐题看截图

### 1.1 dump 里带题干、选项和按钮的 bounds（真实输出）

```bash
dev_sh "uiautomator dump /sdcard/q.xml"
grep -o 'text="[^"]*"[^>]*bounds="[^"]*"' /sdcard/q.xml
```

```text
text="【第1题】" bounds="[36,655][216,703]"
text="（题干原文已隐去）" bounds="[51,766][1170,883]"
text="直接相切连接  " bounds="[225,943][549,1003]"
text="标注联系尺寸,建立位置约束" bounds="[222,1096][816,1156]"
text="不需要任何尺寸联系  " bounds="[225,1249][693,1309]"
text="必须重合在一起 " bounds="[225,1402][582,1462]"
text="上一题" bounds="[66,1588][597,1714]"
text="下一题" bounds="[624,1588][1155,1714]"
```

这些 bounds 就是像素坐标（本例选项行 y=973/1126/1279/1432，与 `px_sel` 的读数一致）。
于是**一题一次 dump 就能同时拿到：题干、全部选项、上一题/下一题/交卷的位置**。

### 1.2 49 题采集 = 一次工具调用

循环体：`dump → 解析「下一题」bounds → 点它 → sleep 1.1`。
实测 **≈7 秒/题**，49 题 ≈5 分钟，产出 49 个 XML；本地用 node 解析成「题干 + 选项 + 每题自己的 y」不到 1 秒。

### 1.3 dump 本身的两个坑（这次都踩到了）

| 现象 | 原因 | 处理 |
|---|---|---|
| dump 出来是**桌面**（微信/QQ/支付宝…） | 采集时应用不在前台 | dump 后检查内容是否含 `【第N题】`，不含就重试（≤3 次）或先 `dev_app` |
| dump 里**混着上一页节点**（作业列表的「测验一/重做/去完成」） | WebView 旧页面仍在无障碍树里 | 以**最后一个** `【第N题】` 为锚点，读到 `下一题/上一题/交卷` 就截断 |

## 2. 发现的问题（按严重程度）

### P0-1　前台守卫在命令替换里偶发返回空 → 误判并重启应用

- **现象**：应用明明在前台，`dev_batch` 仍打印
  `andev: refusing: focused window is not cn.campsg.spoc4 -> `（`->` 后面是空的），
  于是 `dev_seq` 走 `dev_app` 重启应用再重试。
- **证据**：同一次调用的终端里先出现
  `mCurrentFocus=Window{... u0 cn.campsg.spoc4/io.dcloud.PandoraEntryActivity}`，
  紧接着就是 refusing（`$fg` 为空）。说明 `dev_fg` 的输出**没有进入 `$( )`**（落到 stderr 或被空捕获）。
- **影响**：白白多一次重启往返；若在答题中途重启，会回到第 1 题（本次多次发生）。
- **建议**：`dev_fg()` 改为 `dev_sh '...' 2>&1`；`dev_batch` 对**空 fg** 判为「稍后重试一次」，而不是立刻 relaunch。

### P0-2　（我的脚本错误）前台校验失败时没有中止，49 题批量照跑

- **现象**：日志里 `fg=  mCurrentFocus=Window{... com.termux/com.termux.app.TermuxActivity}`，
  脚本仍然执行了整段点按批次 → 部分点击落在 Termux/别处，`Q43–Q49` 状态被改乱，必须返工。
- **用户原话**：「你没切过去你知道吗」。
- **正确写法**：

```bash
fg=$(dev_sh "dumpsys window 2>/dev/null | grep -m1 mCurrentFocus" 2>&1)
case "$fg" in *cn.campsg.spoc4*) ;; *) echo "ABORT: $fg"; exit 1 ;; esac
```

- **建议**：长批量切成 10–15 题一块，**每块开始前重新校验前台**。

### P1-1　返回键不是「返回」，是「确定退出吗？」

在答题页按 `input keyevent 4` 弹出：

```text
提示
你有正在作答的试卷
确定退出吗？          再想想(≈761,1577)   直接退出(≈982,1577)
```

本次它被（我和用户）误读成「要交卷」。文档必须写清这个弹窗的文案与两个按钮的含义。

### P1-2　交卷确认框：两个按钮分不开，而且同一位置可能是别的弹窗

- `px_find red 500,1350,1250,1550` 返回的是**两个按钮文字的合并 bbox**
  `[776,1475][1046,1512] center=(911,1493)`，拿不到单个按钮中心。
  实测：确定 ≈ (802…813, 1493)，取消 ≈ (1003, 1493)。
- 同一坐标位置还可能是**完全不同的弹窗**：过期作业弹「任务已经截止」，只有一个「知道了」≈(1002,1493)。
- **结论**：必须先读弹窗文字再点，不能只按坐标点。

### P1-3　选项行（以及「下一题」按钮）会随题干长度上下移动

本次 49 题里，选项行的 y 实测出现过：

```text
916 942 973 1030 1069 1095 1126 1146 1183 1222 1248 1273
1279 1324 1336 1375 1426 1432 1452 1477 1489
```

「下一题」按钮也不固定，49 题里落在 **y=1531 / 1582 / 1588 / 1633 / 1645** 五档。
→ 任何"记住的 y"都会点错；必须**每题用它自己 dump 出来的 y**。

### P1-4　点完立刻校验会抓到未刷新的帧，而我带着错误交卷了（前一次：另一套卷子只拿了一半分）

- **现象**：点选项后 sleep 1.2–1.5 s 抓帧，`px_sel` 显示 `not-selected`；我没停下重试就继续交卷，
  该题留空 → 该题全部分值丢掉。
- **教训**：**校验失败必须当场重试（重选 + 再校验），绝不带病交卷。**

### P1-5　串页：一处导航失败会污染后面所有题

- **现象**：批量里「上一题/下一题」的坐标取自旧 dump；某一跳没生效后，后续点击落在错误的题上。
  本次把 `Q45/46/47/49` 分别改成了 C→B、B→A、C→B、A→B（复核时才发现）。
- **修复做法**：每一步都**重新 dump 当前页**再取坐标；点完立刻像素校验；解析失败要**显式报错**。
  我在脚本里用 `set -- $nb` 遇到空值，结果是 `input swipe 600 0 600 0 120`——静默点到了 (600,0)。

### P2-1　应用被切后台/重启后，回到的是「作业列表」而不是答题页

`monkey -p cn.campsg.spoc4 -c android.intent.category.LAUNCHER 1` 会回到上次所在课程的作业列表；
「重做」要重走：作业行 → **卡片态**「重做」(≈595,2164) → **全屏态**「重做」(≈595,2427)。
同一个词，两处坐标完全不同。

### P2-2　交卷后作业列表会重排

已完成项会移动位置（本次多次遇到），行的 y 不能复用，每次都要重新定位。

### P2-3　过期作业无法交卷

课后练习（截止 09-22 15:30）：点交卷 → 「任务已经截止」→ 只有「知道了」。
这类作业做之前先看截止时间，避免白做。

### P2-4　被系统打回的作业会变成「待重做」

测验一 昨天未通过 → 今天显示「待重做 / 上次作业成绩 / 打回理由：不及格系统自动打回」。

## 4. 给 skill 的具体修改建议

1. **加"文本优先"路线**：写明该应用 `uiautomator dump` 在 WebView 上**可用**，
   题干/选项/按钮都带 bounds；像素校验只作为"答完之后的确认"。
   附批量采集片段 + 「dump 内容必须含 `【第N题】`，否则重试」的硬规则。
2. **修 `dev_fg()`**：用 `2>&1` 捕获；`dev_batch` 对空 fg 先重试一次再 relaunch。
3. **写清三种弹窗**的文案与按钮坐标：退出确认（再想想/直接退出）、提交确认（确定/取消）、
   过期提示（知道了）。
4. **长批量必须切块**，每块前校验前台（针对 P0-2）。
5. **硬规则：校验通过才允许交卷**；校验失败必须重试（针对 P1-4）。
6. 记录「选项行 y 与下一题按钮 y 都会漂移」，并附本次实测的 y 样本（针对 P1-3）。
7. 补「列表重排 / 过期作业 / 打回重做」三种列表状态的处理（针对 P2-2、P2-3、P2-4）。

# 第二场：某课程「第三周2 课前测验」（2 题）

2026-09-29 08:2x，新版 skill（`dev_dump` / `dev_collect` / `dump_*`）首次实跑。
场景：`<quiz-app>` → 某课程 → 第三周2 → 课前测验（2 题单选）。

## 6.1 新助手的好消息

- `dev_dump` + `dump_nodes` 可用：一次 dump 拿到题干、选项字母、选项文字和按钮真实 bounds。
- `dev_collect 6 下一题 1.0 ~/.mquiz2`：**一次调用**走完整套，产出 `d1.xml` / `d2.xml`。
- 自写解析规则（这次的解析器）：锚点 = **最后一个** `【第N题】`；选项标签 = `^[A-J]$` 且 `x0<200`；
  选项文字 = 同一 y 带（±45）且 `x0∈[200,1150]` 的最近节点。解析结果就是卷面：

```text
Q1 （题干原文已隐去）
   A ...   B ...   C ...   D ...            → 答 D
Q2 （题干原文已隐去）
   A ...   B ...   C ...   D ...            → 答 A
```

## 6.2 新发现的问题

### N1　`dump_find` 是**精确匹配**，问「我在第几题」会直接失败

```text
$ dump_find v1.xml "【第"
no node matched "【第"        # 退出码非 0
```

要子串匹配得用 `dump_any`。建议 SKILL 写明 `find`=精确 / `any`=包含；
或让 `find` 在精确失败后自动回退到包含匹配并提示。

### N2　`dump_quiz` 在这页给出**错的题干**，还把上一页的节点当成「选项」

实测输出：

```text
stem="分值： 2分"
option ... "课中任务"
option ... "课后作业"
option ... "去完成"
```

根因：`quiz` 取了锚点之后的**全部**节点，没有按「选项行几何」过滤，也没有用「最长文本」挑题干。
建议修 `dump.js quiz`：① 只把 `^[A-J]$` 且 `x0<200` 的节点当标签；② 选项文字取同一 y 带（±45）
且 `x0∈[200,1150]` 的最近节点；③ 题干取标签行**之上**最长的文本节点（本例应得题干原文）。

### N3　守卫只在「批量开始前」校验还不够 —— 应用会在批量中途失去前台

本次批量开始前 `dev_fg` 明确 `fg ok`；批量（Q2 选 A → 上一题 → Q1 选 D）执行完，
`dev_dump` 抓到的却是 Termux/桌面，**没有** `【第N题】` 锚点。
结论：**每块批量之后必须立刻再 dump 一次并断言锚点**，把「跑飞」在一个往返内发现；
无锚点就停止后续所有动作，先 `dev_app` 回答题页。

### N4　「无锚点」之后我该做却没做的事

按 SKILL 新规则，无锚点 = 应用不在前台。当时我只打了 `no node matched` 就停了，
没有立刻 `dev_app` + 截图确认。建议把文本流程写成固定三步：

```text
dump → 有【第N题】锚点？ → 没有：dev_app 重试(≤2) → 仍没有：截图给人看
```

### N5　`dev_collect` 的输出是两行，容易读错

```text
$ D=$(dev_collect 6 下一题 1.0 ~/.mquiz2); echo "$D"
2
<local work dir>
```

第一行是远端 `ls | wc -l` 的题目数，第二行才是本地目录。文档应写明「取最后一行」，
或让函数把数量打到 stderr、stdout 只留目录。

|---|---|
| 选项行 Q1 | y=916 / 1069 / 1222 / 1375 |

收尾时应用在后台，`Q1=D / Q2=A` 是否真的落下**尚未校验**。下次进场应先 `dev_dump`
断言锚点 → 逐题像素校验 → 才交卷（新规则：未验证不得交卷）。

1. 修 `dump.js quiz` 的题干 / 选项判定（N2）。
